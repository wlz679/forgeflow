## 这个计算器衡量什么

扩展收入（Expansion Revenue）衡量你从老客户身上新增的经常性收入占
期初 MRR 的比例，是让 SaaS 公司在 GRR 平淡时仍能把 NRR 推到 100% 以上
的顶层增长杠杆。扩展来自两条不同的运动：**升档 upsell**（同一个产品
——更多席位、更高档位、更多用量）和**交叉销售 cross-sell**（卖给同一
客户你组合里的另一个产品）。本工具把这两种分开计量，让你看清扩展引擎
到底由哪条动作驱动——这种拆分很关键，因为这两种运动的毛利、销售周期
和产品适配前提都不同。

## 计算方法

我们使用的 v3 标准公式：

```
扩展 MRR   = 升档 MRR + 交叉销售 MRR
扩展 (%)   = 扩展 MRR ÷ 期初 MRR × 100
```

| 变量          | 含义                                          |
| ------------- | --------------------------------------------- |
| `期初 MRR`    | 期初所有老客户的总 MRR                        |
| `升档 MRR`    | 同一产品更多席位 / 更高档 / 更多用量的净增 MRR |
| `交叉销售 MRR`| 卖给已有客户你组合中另一个产品的 MRR          |

`期初 MRR = 0` 时返回扩展 = 0（除零保护）。健康带沿用 OpenView /
ICONIQ 中端市场 SaaS 基准：🟢 ≥25%（顶四分位）、🟡 15–25%（顶四分位
中端市场）、🟠 5–15%（有动作但偏弱）、🔴 <5%（无扩展动作，纯留存
打法）。所有输入都截断为非负。

## 局限性 / 何时不适用

扩展收入是 **B2B 中端市场 SaaS** 指标。它不能直接套到自服务型 C 端
产品（扩展稀少且不均），也不适用于没有多产品组合可以交叉销售的服务型
业务。这个指标还**高度依赖 GTM**——纯 PLG 模式的扩展主要来自用量档
升级，而销售导向的企业级模式主要来自 ACV 提升——这两套运营手册完全不
一样。此外，upsell/cross-sell 的拆分取决于你的产品矩阵；如果定价档位
本身不清，数字就分不干净。搭配 **NRR 计算器** 可以看到扩展对净留存
的提升作用，搭配**客户流失率计算器**可以确认扩展引擎没有掩盖流失。

## 案例走读

假设一家 B2B SaaS 期初 MRR $1,000,000，Q2 期间跑出有条不紊的扩展动作：
在成长型客户团队上加席位 = **升档 $120,000**，把分析附加模块卖给已在
用核心产品的客户 = **交叉销售 $50,000**。走一遍：

1. `期初 MRR` = $1,000,000
2. `升档 MRR`（老客加席位）= +$120,000
3. `交叉销售 MRR`（分析附加模块）= +$50,000
4. `总扩展 MRR` = $120,000 + $50,000 = **$170,000**
5. `扩展 %` = $170,000 ÷ $1,000,000 × 100 = **17%** → 🟡 健康

搭配 **NRR 计算器**：同期还有 $80,000 缩减和 $20,000 流失，NRR 落在
107%——正好说明扩展引擎把 NRR 拉过了 100% 损益平衡线。
