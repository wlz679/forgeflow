## 这个计算器衡量什么

文章实用性通过两个指标的复合来衡量知识库内容质量——点赞占比（👍 ÷
总投票数）与投票率（总投票数 ÷ 文章浏览数）。一个知识库即使覆盖完整、
搜索可调，仍然可能内容不实用：客户找到文章、读一遍、关掉页面，回头
照样提工单。👍/👎 投票循环是大规模捕捉这种隐形失败的唯一信号；TSIA
Knowledge-Centered Service 框架把每篇文章的实用性视为"这篇文档解决了
问题吗"的最贴近下游代理指标。点赞占比单独看会过度加权活跃投票者
（小样本偏差），所以与投票率组合，既能捕捉内容质量问题，也能捕捉 UI
提示设计问题。

## 计算方法

```
点赞占比 = 点赞数 ÷ (点赞数 + 点踩数)
投票率   = (点赞数 + 点踩数) ÷ 文章浏览总数
差距     = 目标点赞% − 点赞占比 × 100
```

| 变量              | 含义                                            |
| ----------------- | ----------------------------------------------- |
| `文章浏览总数`    | 整库月度独立文章页浏览数                        |
| `点赞投票`        | 当月所有文章 👍 汇总                             |
| `点踩投票`        | 当月所有文章 👎 汇总                             |
| `知识库总文章数`  | 现役文章数（决定底部 20% 待审数量）             |
| `目标点赞占比%`   | 内部 👍 占比目标——仅作信息提示                  |

健康等级采用复合 AND 逻辑（两个条件同时满足）：
🟢 Excellent（点赞 ≥85% 且投票率 ≥15%）· 🟡 Good（点赞 ≥70% 且投票
率 ≥8%）· 🟠 Warning（点赞 ≥55%）；🔴 Critical（点赞 <55% 或投票率
<3%）。

## 局限性 / 何时不适用

"这篇文章对您有帮助吗？"组件必须位置显眼且不打扰——放在页面底部的
投票组件参与率普遍 <5%；放在文章中段（操作步骤之后）的组件参与率能达
到 15-25%。如果你的组件投票率结构性偏低（<8%），这个指标衡量的其实
是 UI 摆放位置，而不是内容质量。另外，点赞占比在总票数很少时统计噪
声很大——月总票 <200 时，个位数票的增减会让点赞占比波动 2-3pp；请在
票数跨过门槛前把等级视为方向性参考。产品复杂度会显著影响这个指标：
一篇 10 步 API 鉴权文章即便写得完美，也通常停留在 60-70% 点赞，因为
第 9 步有 4 种可能分支。

## 案例走读

假设一家中型 B2B SaaS 月文章浏览 25,000 次、👍 2,400 票、👎 700 票
（总投票 3,100）、知识库总文章数 500 篇、内部 👍 占比目标 75%：

1. `点赞占比` = 2,400 ÷ 3,100 = **77.4%** · `投票率` = 3,100 ÷ 25,000 = **12.4%**
2. Good 等级两个条件同时满足（≥70% 且 ≥8%）→ 🟡 **Good** 等级
3. `差距` = 75 − 77.4 = **−2.4pp**（负数=已超目标，状态良好）
4. 要达到 🟢 Excellent（点赞 ≥85% 且投票率 ≥15%）：需新增 **235 个**
   👍 或新增 **650 张** 总投票数——后者通常意味着把投票组件挪到文章中段
5. 审计底部约 **100 篇文章**（约知识库的 20%）——按 👎 降序排序、相似
   标题分组、重写这一批

搭配**搜索有效性**（K-3）：高点击率 + 低点赞占比是内容问题（刷新
Top 20 不实用）；低点击率 + 高点赞占比是分类法问题（搜索需要扩展同义词）。
