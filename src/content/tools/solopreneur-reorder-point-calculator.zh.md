## 这个计算器衡量什么

补货点（Reorder Point, ROP）是「库存降到多少就该下补货单」的临界值——
**在断货之前**。算错任何一边都贵：算低了会缺货、丢客户（见缺货成本计
算器）；算高了会把钱压在滞销库存里（见持有成本计算器）。本计算器把
**前置期需求**与**服务水平 Z 分数**叠加，让缓冲按统计方法确定而不是
拍脑袋。

## 计算方法

v3 标准公式如下：

```
前置期需求 = 日均需求 × 前置期天数
安全库存   = Z × 需求标准差 × √(前置期天数 / 复盘周期)
补货点     = 前置期需求 + 安全库存
```

| 变量         | 含义                                                                  |
| ------------ | --------------------------------------------------------------------- |
| `日均需求`   | 每天售出件数（可用 30/60/90 天移动平均）                             |
| `前置期天数` | 从下单到到货的天数                                                    |
| `服务水平`   | 周期服务水平目标：90% / 95% / 99% → Z = 1.28 / 1.65 / 2.33           |
| `需求标准差` | 每日需求标准差（用历史周度波动）                                      |
| `复盘周期`   | 多长时间看一次库存并补货（默认 7 = 周度）                             |

√(前置期 / 复盘周期) 因子体现了「你可能在周期中遭遇需求尖峰」的风险——
前置期相对复盘节奏越长，所需安全库存越大，但只按平方根增长。服务水平
Z 分数遵循 SCOR 模型与 APICS CSCP 知识体系。健康度分档：🟢 ≥ 95% · 🟡
90% · 🟠 85% · 🔴 < 85%。

## 局限性 / 何时不适用

模型假设需求**平稳**——没有趋势、没有季节性。服装、节日或任何需求波
动 3×+ 的 SKU，在代入前先用季节指数放大前置期需求。生鲜品还要再扣减
剩余保质期。模型是**单 SKU 口径**——**逐 SKU 计算再汇总**，不要在品类
合计上算补货点，否则安全库存会严重失真。前置期波动会放大断
货风险——APICS/ASCM 建议由 MAD 推算 σ 须乘 1.25。

## 案例走读

一家 DTC 品牌日销 50 件、前置期 14 天、服务水平 95%（Z = 1.65）、
需求标准差 10 件/天、复盘周期 7 天：

1. `前置期需求` = 50 × 14 = **700 件**
2. `安全库存` = 1.65 × 10 × √(14/7) = 1.65 × 10 × 1.414 ≈ **23 件**
3. `补货点` = 700 + 23 = **723 件** → 库存到 723 件即下单。
4. What-If：前置期翻倍至 28 天 → ROP 升至 1,433 件，安全库存只增加
   10 件（√2 因子，不是 2×）。
5. 与「缺货成本计算器」配合：723 件门槛对应每年约 51 单、1,200 件缓冲
   ——可向财务量化「少损失多少销售额」，证明安全库存投入划算。
