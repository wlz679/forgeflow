## 这个计算器衡量什么

产品内事件漏斗衡量从一个产品行为环节进展到下一个环节的用户
百分比——注册 → 首次操作 → 第二次操作 → 转化。端到端转化率
（末步 ÷ 入口步）揭示用户在哪里被卡住，这是每个 PM 做增长诊断
的基石。和营销漏斗（追踪曝光到付费客户）不同，产品内漏斗
追踪事件到事件，让产品团队能真正优化拉动注册后体验的关键节点。

## 计算方法

我们使用的 v3 标准公式：

```
端到端转化 = 末步 / 第1步
步转化率_i = 第(i+1)步 / 第i步
最大流失步  = argmax(第(i-1)步 − 第i步)  // 按绝对人数，不是百分比
```

| 变量           | 含义                                                       |
| -------------- | ---------------------------------------------------------- |
| `第1步`        | 触发入口事件的用户数（如注册）                             |
| `末步`         | 触达终点事件的用户数（如转化）                             |
| `步转化率_i`   | 每步留存百分比（第2/1、第3/2、……）                        |
| `最大流失步`   | 绝对人数丢失最大的相邻两步                                 |

社区基准下的健康带：绿 ≥40% · 黄 25–40% · 橙 15–25% · 红 <15%。
逐步留存率揭示是漏斗顶部流失（多为新手引导），还是中段（价值
发现）或深段（转化摩擦）。

## 局限性 / 何时不适用

漏斗步转化是**绝对事件**指标——它只能告诉你流失**在哪**，不能
告诉你**为什么**。要做诊断，配合会话回放、定性用户访谈和事件
属性的细分。它也漏掉了跳过步骤或晚些返回的用户，所以对开放式
探索路径，请改用 pathing 分析。最后，稳态下任意步骤为 0 几乎
总是事件埋点 bug，不是真实产品现象——优化前先确认埋点正确。

## 案例走读

一家 B2B SaaS 有 5 步产品漏斗，想知道激活卡在哪里。从 Mixpanel
拉过去 30 天的用户数：`1000 → 800 → 500 → 320 → 210`。

1. `端到端转化` = 210 / 1000 = **21.0%**（橙带——有实质流失）。
2. 各步转化率：800/1000 = 80.0% · 500/800 = 62.5% · 320/500 = 64.0% · 210/320 = 65.6%。
3. `最大流失步` 是第2→3步（丢失 300 人）。这正是价值发现步——用户首次接触核心功能的环节。
4. Break-Even：要达成绿带（40% 端到端），末步至少需要 **400 用户**（目前 210）。把第2→3 步优化 +20 个百分点，端到端转化可拉到约 27%。
5. Milestone 段建议：先简化价值发现步，下个迭代再复测漏斗。配合 **Activation Rate Calculator** 验证用户在第5步后是否真的完成了激活。
