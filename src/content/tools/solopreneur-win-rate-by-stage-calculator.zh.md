## 这个计算器衡量什么

分阶段赢率通过把整体赢率拆解为四个相乘的阶段转化（SQL→Opp、Opp→Proposal、Proposal→Negotiation、Negotiation→Won），揭示你的漏斗到底在哪一段漏得最狠。它会识别出唯一的最弱瓶颈阶段——因为漏斗数学是相乘的：改进这一段会顺着后面的所有阶段叠加放大。HubSpot 2026 基准给出 B2B SaaS 中位数赢率为 15–25%；Gartner 2026 报告显示顶级分位团队通过死磕最弱阶段做到 ≥25%，而不是堆更多 SQL。

## 计算方法

我们使用的 v3 标准公式把漏斗视作相乘的级联：

```
阶段率[i]      = 推进数 ÷ 进入数          // 每段转化率
整体赢率        = 阶段率[0] × 阶段率[1] × 阶段率[2] × 阶段率[3]
瓶颈阶段        = argmin(阶段率)          // 0 索引
```

| 变量            | 含义                                                  |
| --------------- | ----------------------------------------------------- |
| `SQL→Opp`       | MQL/SQL 资格审核到合格商机                            |
| `Opp→Proposal`  | 探索到主动评估并记录需求                              |
| `Proposal→Neg`  | 价格对齐到法务/采购谈判                                |
| `Neg→Won`       | 最终谈判到签约                                         |

**健康分档**（整体赢率 × 100）：
- 🟢 ≥ 25% —— 优秀（顶级 B2B SaaS）
- 🟡 15%–25% —— 良好（中端 B2B SaaS 典型）
- 🟠 5%–15% —— 警告（某段或多段严重漏单）
- 🔴 < 5% —— 严重（漏斗重建迫在眉睫）

**假设。** 每个阶段转化在相乘模型里相互独立——现实中它们相关（一个质量差的 SQL 在后面每段都会输），所以瓶颈诊断是最优先的杠杆。阶段率用原始进入/推进数（未四舍五入的中间值）计算，避免浮点漂移。取近 6 个月批次以平滑季节性。

## 局限性 / 何时不适用

分阶段赢率为**B2B SaaS 或有明确阶段门槛的顾问式销售**设计。不适用于事务型或自助式 funnel——这些场景阶段边界不清晰。它还假设销售如实更新阶段进度——如果"推进到 Proposal"只是行政勾选而非有意义的事件，阶段率会低估真实瓶颈。相乘模型隐含阶段独立；对强相关漏斗（例如逐阶段采购的企业销售）请补充批次分析。样本太小（每段 <30 单）会让率值噪声偏大——合并 2–3 个季度数据再做结论。

## 案例走读

某 B2B SaaS 漏斗：100 SQL 进入 → 50 推进到 Opp → 30 到 Proposal → 20 到 Negotiation → 15 赢单：

1. `SQL→Opp` = 50 ÷ 100 = **50.0%**
2. `Opp→Proposal` = 30 ÷ 50 = **60.0%**
3. `Proposal→Neg` = 20 ÷ 30 = **66.7%**
4. `Negotiation→Won` = 15 ÷ 20 = **75.0%**
5. `整体赢率` = 0.50 × 0.60 × 0.667 × 0.75 = **15%**
6. 瓶颈：**SQL→Opp 50.0%**（最低阶段率）
7. 健康分档：🟡 Good（15–25%）—— 中端典型
8. What-if：把 SQL→Opp 从 50% 提到 65% → 整体跳到 20%（+5pp）；把 Negotiation→Won 从 75% 提到 85% → 整体 17%（+2pp）
9. 走向 🟢（25%）：把 SQL→Opp 从 50% 提到 ~83%（或在其他段做等效提升——漏斗顶端的 ROI 最高）
