## 这个计算器衡量什么

库存周转率是衡量一家公司每年平均库存被周转几次的核心指标——DTC、Shopify
和 Amazon FBA 运营者最常被问到的数字。比率越高，说明资金没有沉淀在滞销
SKU 里；比率越低，往往意味着死库存过多、SKU 治理缺位、备货过度。配套
的「销售天数」（Days-to-Sell）把同样公式换算成「我现在手头能撑多少天」
——这是买家、银行和 3PL 在尽调时最爱问的形式。

## 计算方法

v3 标准公式如下：

```
库存周转率 = 年度销售成本 / 平均库存
销售天数   = 期间天数 / 库存周转率
```

| 变量           | 含义                                                                  |
| -------------- | --------------------------------------------------------------------- |
| `年度销售成本` | 一段时间内（通常 365 天）卖出的商品总成本（COGS）                    |
| `平均库存`     | （期初库存 + 期末库存）÷ 2，使用成本或采购价口径                     |
| `期间天数`     | 统计窗口，默认 365（年度）；做季度跟踪可用 90                         |

行业基准（用于健康度分档）：**通用 6×、服装 4×、电子 6×、食品杂货 12×、
家具 3×** 每年。健康度分档：🟢 ≥ 6× · 🟡 4–6× · 🟠 2–4× · 🔴 < 2×。
基准来源遵循 APICS / CSCMP 供应链知识体系，将 4–6× 定为通用零售健康区
间，低于 2× 即被定义为「关键——急需 SKU 治理」。

## 局限性 / 何时不适用

本计算器假设库存是按成本计价的实物库存。**不**覆盖以下场景：易腐品过期
（食品）、寄售库存、生产型在制品（WIP）。如需以上场景，请在模型上叠加
按保质期的损耗子模型。该指标也是**滞后型**指标——4× 年化周转率告诉你
过去发生了什么，而不是下季度会发生什么。请与「补货点计算器」配合，把
历史图景转化为补货计划。

## 案例走读

一家 DTC 服装品牌年度 COGS $240,000、平均库存 $40,000，使用通用基准 6×/年：

1. `库存周转率` = $240,000 / $40,000 = **6.00×/年**
2. `销售天数` = 365 / 6.00 = **60.8 天**
3. 行业基准 = 通用 6×/年 → **处于基准线（🟢）**
4. What-If：销售下滑 10%，COGS 降至 $216,000 → 周转率跌至 5.40×/年，
   销售天数升至 **67.6 天**——资金开始放缓。
5. 与「持有成本计算器」配合：在该品牌 20% 持有费率下，这多出来的 7
   天库存每年约 $40,000 × 20% ≈ $8,000/年的资金占用。
