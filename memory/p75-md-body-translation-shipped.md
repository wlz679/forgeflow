## What shipped

### T1: 100 MD body translations (sonnet subagent)
- Added `bodyZh: |` field to 100 MD files in `src/content/blog/`
- en body byte-exact unchanged
- bodyZh is YAML `|` block scalar preserving newlines

### T2: Wire bodyZh into Astro Content Collection
- **`src/content/config.ts`** — added `bodyZh: z.string().optional()` to blog schema. **Root cause fix** — astro:content's schema was stripping the unknown `bodyZh` field from `entry.data`, so my template condition fell back to EN body. Without schema entry, the YAML parsing was working but the runtime type-check rejected the field.
- **`src/lib/blog.ts`** — added `bodyZh?: string` to `BlogPost` interface. `toBlogPost` reads `entry.data.bodyZh` (typed via `as Record<string, unknown>` to bypass schema narrowing — bodyZh is on the schema now but `entry.data` type still narrow)
- **`src/pages/[lang]/blog/[slug].astro`** — template condition: `(lang === 'zh' && post.bodyZh ? post.bodyZh : post.content).split('\n').map(p => <p>{p}</p>)`. Fallback to en body if bodyZh missing.

## Bug discovered + fixed mid-batch

Initial implementation passed all 1178 tests but dist/zh/blog pages still showed EN body. Diagnosis via TS diagnostic on debug script: `Property 'bodyZh' does not exist on type '{ title: string; excerpt: string; ogImage: string; toolSlug: string; }'` — astro:content's Zod schema rejected the unknown field. Fixed by adding `bodyZh: z.string().optional()` to schema.

**This is a defense-in-depth pattern: TypeScript schema validation can silently strip valid frontmatter fields.** Without TS catching it, the YAML field would be present in dist files but `entry.data.bodyZh` would be undefined at runtime.

## Why this exists

P72 i18n audit found 6 user-visible defects (D1-D6). P72 T2-A + P73 fixed D1-D5 (5 render-layer defects). D6 (MD blog bodies) was the last defect: 100 markdown files had EN-only body content, rendered verbatim to zh pages via `post.content.split('\n').map(p => <p>{p}</p>)` in the blog detail template.

Without P75, Chinese visitors to `/zh/blog/best-solopreneur-mrr-calculator/` saw:
- ✅ zh title (fixed by P69)
- ✅ zh excerpt (fixed by P69)
- ❌ EN body content ("## What is the MRR Calculator?", "Every successful business owner knows that the right tools make a huge difference.", etc.)

After P75, all body content is in zh.
