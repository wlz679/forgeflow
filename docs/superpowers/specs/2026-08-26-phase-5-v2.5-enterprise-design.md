# Phase 5-A v2.5 Enterprise — Design Spec

> **For agentic workers:** Brainstorming-approved design. Phase 5-A only (Enterprise features sub-project per user decision 2026-08-26). B (AI Native) + C (OS docs) deferred to separate specs.

**Goal:** Add client-side Enterprise experience layer to existing 100-calculator SSG site — Saved Scenarios + Decision Templates + Decision Reports. Zero backend, SSG-compatible, 9/01 AdSense re-apply unaffected.

**Architecture:** 3 features (A1 Saved / A2 Templates / A3 Reports) sharing one localStorage layer with 3 independent keys + shared `EnterpriseToolbar` component + per-feature modal/picker UI.

**Tech Stack:** Astro 4.16.19 + TypeScript 5.6 strict + jsPDF (lazy-imported) + existing Tailwind CSS 4. No backend. No new persistent service.

---

## Global Constraints

- **No backend.** All persistence is client-side `localStorage`. Static SSG architecture preserved.
- **i18n parity en + zh** required for all new keys (per project convention; P103 dead-keys-guard).
- **No external analytics** (PII risk). Console logging only.
- **pnpm check 0 errors** before commit (per CLAUDE.md mandate).
- **Source-only tests** default mode (per project convention). Build-dep tests run via `RUN_BUILD_TESTS=1`.
- **No new engines / categories** (P16 milestone lock at 100). Pure feature layer.
- **9/01 AdSense re-apply unaffected** — Phase 5 ships on `feature/phase-5-v2.5-enterprise-ai-native` branch; merge timing decided by user after ship.

### 1.2 Storage Layer Design

3 independent `localStorage` keys with shared schema:

```typescript
export interface StoredScenario {
  id: string;          // uuid v4
  calcSlug: string;    // e.g. 'solopreneur-mrr-calculator'
  label: string;       // user-provided name (1-50 chars)
  notes?: string;      // optional (1-200 chars)
  inputs: Record<string, number | string>;
  outputs: Record<string, number | string>;
  schemaVersion: 1;    // for migration
  createdAt: string;   // ISO timestamp
  updatedAt: string;
}

const KEYS = {
  scenarios: 'ffk.scenarios.v1',        // A1 — max 50 items
  templates: 'ffk.templates.v1',        // A2 — max 20 items
  reportConfig: 'ffk.reportConfig.v1',  // A3 — last-used config (1 item)
} as const;
```

**Storage envelope** (versioned JSON):
```typescript
type StorageEnvelope<T> = {
  schemaVersion: 1;
  data: T;
};
```

## 2. Components

### 2.1 `src/lib/enterprise/storage.ts`

**Public API**:
```typescript
export function safeStorageGet<T>(key: string, fallback: T): T;
export function safeStorageSet(key: string, value: unknown): boolean;
export function safeStorageDelete(key: string): boolean;
export function safeStorageList<T>(key: string): T[];
```

**Behavior**:
- `safeStorageGet`: parses JSON envelope; on parse error or schema mismatch → returns `fallback` + logs warn
- `safeStorageSet`: writes JSON envelope; on quota or disabled → returns `false` + logs error
- All functions return immediately (no awaiting); no exceptions leak

### 2.2 `EnterpriseToolbar.astro`

**Location**: `[slug].astro` bottom, just before `<EeatTrustBlock>`

**UI**:
```
┌──────────────────────────────────────────────┐
│  Enterprise Toolbar                          │
│  [💾 Save] [📋 Templates ▼] [📄 Report]      │
└──────────────────────────────────────────────┘
```

**Client island**: Each button calls a JS function that mounts the corresponding modal/picker.

**Visibility**: Toolbar renders even if localStorage disabled (E1); buttons disabled + tooltip shown.

### 2.3 A1 `SaveScenarioModal.astro`

**Trigger**: Click `[💾 Save]` in toolbar

**Fields**:
- Name (required, 1-50 chars) — prefilled with auto-suggestion like "MRR Calc · 2026-08-26"
- Notes (optional, max 200 chars)

**Action**: On save → `scenario-manager.save({ calcSlug, label, notes, inputs, outputs })` → success toast → modal close

### 2.4 A2 `TemplatePicker.astro`

**Trigger**: Click `[📋 Templates ▼]` in toolbar

**List**: Filters templates by `calcSlug === current` (exact match — no fuzzy). Sorted by `updatedAt desc`. Max 10 displayed.

**Per-item actions**:
- `[Apply]` → `template-manager.apply(id)` → sets form inputs → triggers calculate → toast
- `[Delete]` → confirm dialog → `template-manager.delete(id)` → toast

**Header action**: `[+ Save current as template]` → opens inline name input → saves

### 2.5 A3 `ReportGenerator.astro`

**Trigger**: Click `[📄 Report]` in toolbar

**Fields**:
- Title (required, 1-80 chars) — prefilled with "ForgeFlowKit · {calcSlug} · {date}"
- Format: PDF (default) / HTML

**Action**: On generate →
- PDF: lazy-import jsPDF → build PDF → `browser.download('forgeflowkit-{slug}-{date}.pdf')`
- HTML: build HTML string → new tab → `print()`

**Future**: Email option (Phase 5-A.2 / v3.0+)

## 3. Data Flow

### 3.1 Save Scenario (A1)

```
User in calc form → customFn calculates → outputs render
   ↓ click [💾 Save]
Modal opens, prefilled with current inputs + outputs
   ↓ user edits name + notes → click [Save]
scenario-manager.save({...})  ↓
localStorage.setItem('ffk.scenarios.v1', JSON.stringify({schemaVersion:1, data: [...prev, new]}))
   ↓ success toast (3s)
Modal closes
```

**Edge case (E2)**: quota exceeded → catch → toast "Storage full. Delete old scenarios first." + suggest open /scenarios/ page.

### 3.2 Apply Template (A2)

```
User click [📋 Templates] → Picker opens
   ↓ Fetch + filter localStorage by current calcSlug
Render list (max 10, sorted by updatedAt desc)
   ↓ User clicks [Apply] on template
template-manager.apply(id)
   ↓ Get template → extract inputs (only matching keys for current calc)
   ↓ Set each input.value via DOM `input[name="..."]` selector
   ↓ Trigger customFn.calculate() → outputs refresh
   ↓ toast "✓ Template applied"
```

**Edge case (schemaVersion mismatch)**: If template's schemaVersion differs from current calc's → warn "Template from older engine version. Some inputs may not apply."

### 3.3 Generate Report (A3)

```
User click [📄 Report] → Modal opens
   ↓ User edits title + selects PDF → click [Generate]
report-builder.generate({ calcSlug, title, inputs, outputs, healthBand, recommendation })
   ↓ Lazy-import jsPDF on first call (cached after)
   ↓ Build PDF sections:
     - Header: ForgeFlowKit logo + title + date
     - Section 1: Calc name + URL
     - Section 2: Inputs table (label + value)
     - Section 3: Outputs table (label + value + health band emoji)
     - Section 4: Decision recommendation (if available)
     - Footer: "Generated by ForgeFlowKit · {date}"
   ↓ jsPDF.output('blob') → browser.download(filename)
   ↓ toast "✓ Report downloaded"
```

**Edge case (E5)**: jsPDF import fails → toast "PDF library failed. Try HTML format." + fallback to HTML.

### 3.4 Cross-Feature

| Scenario | Behavior |
|---|---|
| Save scenario → apply template → save as template | 3 independent flows. localStorage keys don't share data. |
| Scenario from old engine schema applied to new engine | schemaVersion mismatch → warn + skip non-matching keys |
| User has 50 scenarios + applies 1 + deletes 1 | list rewrite OK (small payloads ~5KB each) |
| Multiple tabs open same calc, user saves in tab1 | `storage` event listener → tab2 reloads templates |

### 3.5 localStorage Quota

- Scenarios: 50 max (warn at 40, hard cap at 50)
- Templates: 20 max (warn at 15, hard cap at 20)
- ReportConfig: 1 only (last-used config)
- **Estimate**: 50 × 5KB = 250KB total (well under 5MB localStorage limit)

## 4. Error Handling

### 4.1 Error Categories

| ID | Error | Detection | UX | Logging |
|---|---|---|---|---|
| **E1** | localStorage disabled | `try { localStorage.setItem(...) } catch` (Safari private / corporate policy) | Disable all toolbar buttons + tooltip "Storage unavailable" | console.warn |
| **E2** | Quota exceeded | `try { setItem } catch (QuotaExceededError)` | Toast "Storage full. Delete old scenarios first." | console.warn |
| **E3** | JSON parse failure | `try { JSON.parse(...) } catch` (corrupted storage) | Auto-reset to empty + toast "Storage reset" | console.error |
| **E4** | Schema version mismatch | envelope.schemaVersion !== 1 | Trigger migration OR reset + warn | console.warn |
| **E5** | jsPDF load failure | `await import('jspdf')` rejects | Toast "PDF library failed. Try HTML format." + fallback | console.error |
| **E6** | User input invalid | Empty label / label > 50 chars | Disable [Save] button + inline error | console.debug |
| **E7** | Cross-tab conflict | `storage` event listener sees conflicting write | Last-write-wins (storage event timestamp) + toast "Updated from another tab" | silent |

### 4.2 Safe Storage Wrappers

```typescript
export function safeStorageGet<T>(key: string, fallback: T): T {
  try {
    const raw = localStorage.getItem(key);
    if (!raw) return fallback;
    const parsed = JSON.parse(raw);
    if (!parsed.schemaVersion || parsed.schemaVersion !== CURRENT_VERSION) {
      return migrate(parsed, fallback);
    }
    return parsed.data as T;
  } catch (err) {
    console.warn(`[enterprise] ${key} storage failed:`, err);
    return fallback;
  }
}
```

### 4.3 Migration Strategy

- **v1 → v2**: If old data lacks `schemaVersion` → auto-wrap as v1 read-only. New writes always v2.
- **Breaking change**: Add new key (`ffk.scenarios.v2`) → migrate v1 → v2 → delete v1.
- **Backward compat**: Read both v1 + v2 for 1 release cycle.

### 4.4 Toast System

4-variant toast helper, 30 lines, no new lib:
```typescript
function showToast(message: string, variant: 'success'|'error'|'info'|'warn', durationMs = 3000): void
```

- Auto-dismiss 3s
- Stack max 3 (latest on top)

## 9. Risks

| Risk | Mitigation |
|---|---|
| 9/01 AdSense re-apply sees new toolbar buttons as "low-value UI clutter" | Toolbar is below content + non-intrusive; doesn't replace existing UX |
| jsPDF bundle size (~50KB minified) increases page weight | Lazy-load on first report generate; not blocking initial render |
| localStorage corruption from browser bugs | Safe wrappers + auto-reset on parse failure (E3) |
| User saves PII in scenario labels | No telemetry; UI labels are user-controlled; no exfiltration |
| Cross-tab sync causes UX confusion | StorageEvent triggers, but toast "Updated from another tab" sets expectation |
| Schema migration breaks existing users' saved scenarios | v1→v2 backward compat for 1 release cycle |
