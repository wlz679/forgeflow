## Global Constraints

- **英文页必须逐字不变**：token 的英文兜底必须与改写前的原文**逐字相同** ⇒ G9 守；兜底里多一个空格都算回归。
- **G9 基线钉在本批之前**：baseline = `9abe1f0`（B3-14 令牌化之前的最后一个提交）⇒ **不得用 HEAD**（否则变成 token vs token 真空绿）。
- **改写 = 重写整个引擎文件**：FAQ / description / howToUse 也在文件里 ⇒ 不许顺手改文案；要改必须同步 locale。
- **跨引擎共享 code 的英文必须逐字一致**：同名 label 若措辞不同 ⇒ 拆新 code，不许复用（B3-8 实测教训）。
- **locale 只走工具落库**：`p168-locale-merge`（保键序 + 占位符守恒 + emoji 取源）⇒ **禁止手改 locale JSON**。
- **翻译 worker 只产出「code→中文」清单**：不碰引擎文件、不碰 locale JSON ⇒ 落库永远走工具。
- **模板不得冻结数值**：locale 模板里的数值会直接显示给用户 ⇒ 一切运行时数值必须走 `{param}`。
- **健康度 4 档各写一个 code 字面量**：动态拼码静态扫描认不出 ⇒ 会被守卫判成未声明。
- **`staticExamples[0]` 由 codegen 重生成**：不许手写（`codegen-examples --check` 会报漂移）。
- **目标状态型守卫必须与修复同 commit 落库**：每笔提交里「新增进 TOKENIZED 的引擎」必须已完全令牌化，否则 CI 红。
- **判据口径**：只做到 **zh 整行英文 = 0**（G4c）；另有中英混排不在本批范围（用户 2026-11-19 拍板）。
- **台账只能变小不能变大**：`DEBT_MAX` 随销账下调（45 → 27）⇒ 修好一条销一条。
- 一条变异只红一条断言；变异必须真的改到文件；还原无条件执行 + sha256 逐字节校验。
- 提交前 `git fetch` + 确认 0 behind；禁止 force-push；commit 信息 = `type(scope): 中文标题` + 正文含实测数字 + **维度 3 scan 声明**；不得含 `[CI Skip]` 类标记。
- ⛔ `bing-block-urls.csv` 是无关文件，**不得提交**。
- **G4c 的覆盖范围 = TOKENIZED** ⇒ 引擎入清单 = 四个守卫同步扩到它 ⇒ 入清单的**那一刻**该引擎必须已令牌化。

**两处都不得写进仓库 config**（避免残留代理设置）。
